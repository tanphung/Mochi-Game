# Mochi - On-chain AI Pet and Quest Evaluator on GenLayer

Mochi is a GenLayer dApp where each wallet raises an on-chain pet, chats with an AI companion, customizes a room, mints shareable cards, and uses a Quest Evaluator to judge real public submission links before sending them to a community quest.

## Why This Needs GenLayer

The core scoring feature is the Quest Evaluator. A user pastes quest requirements plus public evidence links, then the Intelligent Contract:

1. Fetches the public evidence on-chain with `gl.nondet.web.get`.
2. Uses `gl.nondet.exec_prompt` to judge whether the evidence satisfies each requirement.
3. Stores the final verdict and reasons on-chain.
4. Uses a custom validator to enforce the semantic verdict: `passed` is only valid when every requirement is `met` and at least one public evidence link was fetched.

Without GenLayer, this becomes a normal off-chain AI checker. The trust-critical part would be run by the app server or one person, which is exactly what this design avoids.

## Main User Flow

1. Connect an EVM wallet and switch to GenLayer Studio/Bradbury-compatible network settings.
2. Create one Mochi pet for the connected address.
3. Care for the pet with on-chain actions: feed, play, sleep, clean.
4. Chat with Mochi; the reply is generated by GenLayer AI consensus and stored in `last_response`.
5. Open "Let Mochi Check Your Quest".
6. Paste quest requirements and public evidence URLs.
7. Submit the evaluation transaction.
8. View the on-chain AI verdict, requirement-by-requirement reasons, evidence fetch count, semantic validator check, and GenLayer tx hash.

## Contract Quality Highlights

- Pinned GenVM runner in `contracts/mochi_pet.py`.
- GenLayer storage types: `TreeMap`, `@allow_storage` dataclasses, and sized integer fields.
- Defensive LLM parsing: strips markdown fences, validates JSON, normalizes statuses, bounds all stored strings.
- Custom nondeterministic validators for chat and quest evaluation.
- Semantic verdict guard for Quest Evaluator:
  - no fetched public evidence means `needs_work`
  - any `partial` or `missing` requirement means `needs_work`
  - `passed` requires all requirements to be `met`
  - validator recomputes and rejects mismatched `meaning_check`
- Edge-case handling for empty requirements, invalid evidence JSON, invalid URLs, too many evidence items, broken/unreachable links, and malformed LLM JSON.

## Project Structure

- `contracts/mochi_pet.py` - GenLayer Intelligent Contract.
- `test/test_mochi_pet.py` - direct-mode tests for pet state, chat, customization, minting, and quest evaluation semantics.
- `deploy/deployScript.ts` - GenLayer deployment script.
- `frontend/` - Next.js app using `genlayer-js`.
- `frontend/lib/contracts/MochiPet.ts` - typed contract client wrapper.
- `frontend/lib/store/petStore.tsx` - app state and contract flow orchestration.
- `frontend/components/mochi/QuestEvaluator.tsx` - UX for public evidence review and AI verdict display.

## Local Setup

Install dependencies:

```shell
npm install
cd frontend
npm install
```

Create `frontend/.env`:

```shell
NEXT_PUBLIC_GENLAYER_RPC_URL=https://studio.genlayer.com/api
NEXT_PUBLIC_GENLAYER_CHAIN_ID=61999
NEXT_PUBLIC_GENLAYER_CHAIN_NAME=GenLayer Studio
NEXT_PUBLIC_GENLAYER_SYMBOL=GEN
NEXT_PUBLIC_CONTRACT_ADDRESS=0xCf3b9e426c56248762786d21a8a5fd816212fc6f
```

Run the frontend:

```shell
cd frontend
npm run dev
```

Deploy a new contract:

```shell
genlayer network set testnet-bradbury
npm run deploy
```

After a contract redeploy, update `frontend/.env`, Vercel build env, and the contract address in this README.

## Verification Commands

```shell
genvm-lint check contracts/mochi_pet.py --json
cd frontend
npx tsc --noEmit
npm run build
```

Direct tests:

```shell
pytest test/test_mochi_pet.py -v
```

On Windows, `test/conftest.py` defers `gltest.direct` temporary stdin cleanup until after stdin is restored, so direct-mode tests can run locally without patching installed site-packages.
